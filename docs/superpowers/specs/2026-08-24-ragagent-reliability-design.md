# RagAgent 可靠性优化设计

## 背景与目标

当前界面保存并展示历史消息，但 `ReactAgent.execute_stream` 仅向模型提交本轮问题；文档索引先写 Chroma、再写 SQLite MD5，文件更新和中途失败会造成旧分块残留或重复；外部记录用字符串拆分 CSV；配置和 README 的聊天模型密钥名不一致，依赖也未形成可复现清单。

本次修改只处理上述真实调用链，不重写 Agent、RAG 或 UI 框架。交付必须包含自动化回归测试、依赖与配置说明，并保持日志不记录 API key 或文档正文。

## 会话上下文

定义统一消息结构：每条消息仅包含 `role`（`user` 或 `assistant`）和字符串 `content`。Streamlit 继续拥有 UI 会话状态；调用 `execute_stream` 时显式传入此前已完成的消息历史，本轮用户消息由 `execute_stream` 追加一次，避免 UI 显示记录与模型输入混用。

历史裁剪同时满足两个边界：最多保留最近 20 条有效消息，并从最新消息向前累计最多 8,000 个字符。裁剪保持原顺序、丢弃空内容和不支持的角色，不允许历史覆盖或注入系统提示词。系统提示词仍只由 `create_agent` 的 `system_prompt` 管理。清空 Streamlit 的消息列表后，下一轮调用得到空历史，因此不能继续引用先前上下文。

测试通过可观测的 Agent 输入验证：第二轮包含第一轮用户与助手消息；清空后仅包含当前问题；超出条数或字符上限时只保留最新的完整消息。流式增量行为保持兼容。

## 文档索引一致性

SQLite 从仅保存 MD5 改为保存每个源文件的索引清单，包括稳定 `source_id`、规范化相对路径、当前内容版本、当前分块 ID 集合和更新时间。`source_id` 由相对于知识库根目录的规范化路径确定；内容版本使用文件内容哈希。每个 Chroma 分块 ID 由 `source_id`、内容版本和分块序号确定，分块 metadata 至少保存 `source_id`、`source_path`、`content_version` 和 `chunk_index`。

索引更新采用可重试的版本切换协议：

1. 读取并切分源文件，使用确定性 ID 写入新版本分块。
2. 新版本全部写入成功后，在一个 SQLite 事务中切换清单到新版本。
3. SQLite 提交成功后删除清单记录的旧版本分块。
4. 若新分块写入失败，SQLite 仍指向旧版本；重试会覆盖相同确定性 ID，不增加重复块。
5. 若 SQLite 已切换但旧块删除失败，本次索引报告失败；下次运行根据当前清单识别并清理非当前版本的同源分块，然后安全完成。

相同路径、相同内容直接跳过；内容变化时检索只返回当前版本。删除源文件不在本次自动删除范围内，避免未经授权移除已索引资料；仅记录可诊断提示作为后续治理项。

异常日志只记录源相对路径、阶段、异常类型和安全错误信息，不记录文档正文、模型输入或密钥。

## CSV 解析

外部记录使用标准库 `csv.DictReader`，以 `utf-8-sig` 打开文件。解析器支持引号内逗号、空字段、UTF-8 BOM 和多行字段；按表头名称读取，不依赖固定列位置。缺少必需表头、列数不一致或 CSV 语法错误时，抛出包含源文件相对路径与记录行号的可读异常。

缓存只在完整文件解析成功后一次性替换，避免部分行污染全局 `external_data`。正常查不到用户或月份仍保持返回空字符串的现有契约。

## 配置与依赖

聊天模型统一使用 `GLM_API_KEY`，Embedding 继续使用 `GITHUB_API_KEY`。新增不含真实值的 `.env.example`。README、错误提示与配置文件使用相同名称。

新增 `pyproject.toml`，声明 Python 版本、运行依赖和测试入口；生成等价锁文件以固定解析后的直接及传递依赖。不得提交本机路径、缓存、API key、模型数据或生成的向量库。

## 测试与验收

实施采用测试先行，每个行为先观察预期失败，再写最小实现：

- 会话：多轮引用输入、清空、20 条上限、8,000 字符上限、非法历史过滤。
- 索引：相同文档重复执行不增加块；修改后旧块不再存在；新分块写入失败可重试；SQLite 切换后删除失败可在下次恢复。
- CSV：引号逗号、空字段、BOM、多行字段、缺少表头和畸形记录定位。
- 配置：无密钥样例可安全提交，README 与运行配置一致。

测试使用内存 SQLite、临时目录和行为等价的向量存储假实现；不调用真实模型、外部天气服务或用户生产数据。最终运行完整测试套件、Python 编译检查和精确 `git diff` 审查。真实模型回答质量和已有真实 Chroma 数据迁移作为人工/未验证边界如实报告。
